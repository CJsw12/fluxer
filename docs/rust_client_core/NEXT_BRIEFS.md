## 7. Embeds, link previews and GIFs

**Embed types** (`MessageEmbedTypes`, `packages/constants/src/ChannelConstants.ts:152`): rich, article, link, image, video, audio, gifv, bluesky. Unfurl resolvers: youtube (video), tenor + klipy (gifv: `url` = page URL, `video` = mp4, `thumbnail` = still, provider name set, `fluxer_unfurl/src/resolvers/klipy.rs:67-85`), fxtwitter, bluesky, wikipedia, xkcd, hacker_news, activity_pub, default (og tags -> link/article/image/video).

**Web dispatch** (`ChannelEmbed.tsx`, component `Embed`): `hasRichEmbedContent` = title != null, description, author, footer, fields, or (provider and type != gifv) (`EmbedRenderUtils.ts:12`). If false the embed is media-only, drawn with no card, border or colour bar, in this order:
1. audio with `audio.proxy_url` -> audio player.
2. video: provider host `www.youtube.com` -> YouTube click-to-play thumbnail; otherwise inline video element.
3. image type whose thumbnail has the animated flag -> animated image (`animated=true` proxy URL).
4. gifv (needs valid video, valid thumbnail, embed.url) -> looping, muted, playsInline video element on `video.proxy_url`, GIF badge, play policy via `useShouldAnimate({kind:'gif'})` (autoplay setting, hover, focus, viewport).
5. any valid thumbnail: gif (content_type image/gif or .gif URL) -> animated image; else static image (`?format=webp&width&height`).
Otherwise a rich card (`RichEmbed.tsx`; type bluesky -> `BlueskyEmbed`). `isValidMedia` needs string url and proxy_url plus numeric width and height, else that media is skipped.
Duplicate embeds (same URL as an earlier embed, `isDuplicateEmbedAtIndex`) render nothing. `UserSettings.renderEmbeds` gates all embeds. `MessageFlags.SUPPRESS_EMBEDS = 1<<2` (`ChannelConstants.ts:119`, Rust `content.rs:23`): the server stops generating embeds; the client shows a hover X button (author, or MANAGE_MESSAGES outside DMs, hidden when guild SEND_MESSAGE is disabled; shift-click skips the confirm) that calls `MessageCommands.toggleSuppressEmbeds` (PATCH message flags).

**Rich card layout** (`ChannelEmbed.module.css`): border 1px `--background-modifier-accent`, radius 8px, left colour bar 4px (`embed.color`), padding 12 (bottom 14), outer max width 516 for text (`EMBED_TEXT_OUTER_WIDTH`) and 432 when media is present (`EMBED_MEDIA_MAX_WIDTH`; chrome = 12*2+4+1). Grid: content column plus optional 80x80 thumbnail (radius 4) on the right. Content order: provider (small), author (24px round icon + name, link), title (link if `embed.url`), description (markdown only for type rich/bluesky, `embedAllowsMarkdown`), fields (12-column grid, gap 8; inline fields share a row, others span the row), media block, footer (20px icon, text, dot, timestamp). Inline right thumbnail only when: no video, no image, thumbnail valid, type not article/image (those promote the thumbnail to a full-width image), and no gallery. Gallery: `collectGalleryImages` merges images of consecutive embeds sharing a URL (max 10, `MAX_GALLERY_MEDIA`), mosaic when more than one.
**Sizes** (`MediaDimensionConfig.ts`): embed media fits within 400x300 (tall 450 high); attachments 550x350; aspect preserved via `createCalculator`; media under 40px is not useful.
**Spoiler/NSFW**: embed is a spoiler when its URL appears inside a double-pipe spoiler span in the message content (`getEmbedSpoilerUrls`), covered by `SpoilerOverlay` until clicked. NSFW = `media.nsfw` or flags bit 1<<4 -> `MatureMediaBlurOverlay` until revealed.
